Java 语言基础：JDK、面向对象、集合与异常

YuAn2026-11-042026-11-04

Java 的语法并不难，难的是它背后那一整套概念体系：JDK 和 JRE 有什么区别、为什么 String 不可变、ArrayList 和 LinkedList 该怎么选、checked 和 unchecked 异常有什么不一样。

这篇按「运行环境 → 语言基础 → 面向对象 → 集合 → 异常 → 泛型」的顺序，把这条线走一遍。

一、JDK、JRE、JVM 到底是什么关系

三个词经常被混着说，实际是层层包含的关系：

名称 全称 作用
JVM Java Virtual Machine 执行字节码的虚拟机，Java 跨平台的根基
JRE Java Runtime Environment JVM + 核心类库，只能运行 Java 程序
JDK Java Development Kit JRE + 编译器工具，用来开发 Java 程序

一句话：JDK ⊃ JRE ⊃ JVM。

写代码装 JDK，服务器上只跑程序装 JRE 就够（实际上现在都直接装 JDK，省事）。

编译执行的过程：

.class 是字节码，不是机器码。JVM 负责把它翻译成当前平台的机器指令——这就是”一次编译，到处运行”的原理。跨平台的是字节码和 JVM，不是 Java 语言本身。

二、第一个程序与基本类型

几个必须记住的规则：

  • 文件名必须和 public class 的名字完全一致（含大小写）；
  • 每个语句以分号结尾；
  • main 方法是入口，签名固定为 public static void main(String[] args)。

八种基本类型：

类型 字节 范围 默认值
byte 1 -128 ~ 127 0
short 2 -32768 ~ 32767 0
int 4 ±21 亿 0
long 8 很大 0L
float 4 单精度 0.0f
double 8 双精度 0.0d
char 2 单个字符 ‘\u0000’
boolean 1 true / false false

String 不是基本类型，是引用类型，但用起来像基本类型：

字符串比较一律用 equals，== 比的是地址，这是新手最经典的坑。

三、面向对象：类、继承、接口

三个核心概念：

  • 封装：字段用 private，通过 getter / setter 访问，控制修改逻辑；
  • 继承：extends，Java 只支持单继承；
  • 多态：父类引用指向子类对象，运行时调用子类重写的方法。

接口：比继承更灵活

类只能继承一个父类，但可以实现多个接口。所以设计上有一条经验：面向接口编程，依赖抽象而不是具体实现。

抽象类 接口
关键字 abstract class interface
构造方法 有 没有
成员变量 任意 默认 public static final
方法 抽象 + 具体 抽象 + default / static
多继承 不支持 支持多实现
适用 有共同实现的基类 定义能力契约

四、集合框架

Java 集合分两大体系：Collection（单列）和 Map（键值对）。

List：有序可重复

实现 底层 特点 适用
ArrayList 动态数组 随机访问 O(1)，中间插入 O(n) 默认选它
LinkedList 双向链表 头尾操作 O(1)，随机访问 O(n) 频繁头尾增删
Vector 动态数组 线程安全但慢 已不推荐，用 CopyOnWriteArrayList

Set：不可重复

实现 底层 特点
HashSet HashMap 无序，增删查 O(1)
LinkedHashSet 链表 + 哈希 保留插入顺序
TreeSet 红黑树 自动排序，O(log n)

Map：键值对

HashMap 的三个要点：

  1. 底层是数组 + 链表 + 红黑树，链表长度超过 8 且容量 ≥ 64 时转红黑树；
  2. 默认初始容量 16，负载因子 0.75，扩容是 2 倍；
  3. 作为 key 的对象必须正确重写 hashCode() 和 equals()，否则 get 不到。

怎么选：一张表说清

需求 选择
按索引访问、遍历多 ArrayList
频繁头尾插入删除 LinkedList
去重 HashSet
去重且保留顺序 LinkedHashSet
需要排序 TreeSet / TreeMap
键值映射 HashMap
线程安全 ConcurrentHashMap

注意：HashMap 不是线程安全的，多线程下用 ConcurrentHashMap，不要用 Collections.synchronizedMap（全表锁，性能差）。

五、异常体系

checked 和 unchecked 的区别：

  • checked 异常（继承 Exception 但不继承 RuntimeException）：编译器强制 try-catch 或 throws；
  • unchecked 异常（继承 RuntimeException）：编译器不检查，通常代表代码 bug。

try-with-resources（Java 7+）自动关闭资源，比手写 finally 更安全：

三个原则：

  1. 不要吞异常。catch (Exception e) {} 空实现是最糟的写法；
  2. 不要用异常控制流程。能用 if 判断的别抛异常；
  3. 自定义异常要带上下文。new OrderException("订单 " + id + " 状态不允许取消") 比 new Exception("错误") 有用得多。

六、泛型

泛型让集合能明确元素类型，把运行时错误提前到编译期。

类型擦除：泛型只在编译期有效，编译后会被擦成 Object（或上界）。所以：

  • 不能 new T()；
  • 不能 new T[]；
  • 不能对泛型做 instanceof；
  • 静态方法不能用类的泛型参数。

七、新手最常踩的八个坑

  1. == 比字符串：用 equals；
  2. Integer 缓存陷阱：Integer a = 127, b = 127; a == b 是 true，但换成 128 就是 false（缓存范围 -128~127）；
  3. Arrays.asList 返回定长列表：add 会抛 UnsupportedOperationException；
  4. 遍历时删除元素：for (String s : list) list.remove(s) 会抛 ConcurrentModificationException，用 Iterator.remove()；
  5. HashMap 用可变对象做 key：key 变了就再也 get 不到；
  6. float/double 算钱：用 BigDecimal，并且要用 new BigDecimal("0.1") 而不是 new BigDecimal(0.1)；
  7. null 调用方法：String s = null; s.length() 直接 NPE；
  8. finally 里 return：会覆盖 try 里的返回值，甚至吞掉异常。

小结

  • JDK ⊃ JRE ⊃ JVM，跨平台靠的是字节码和 JVM；
  • 字符串比较用 equals，别用 ==；
  • 类单继承、接口多实现，面向接口编程；
  • 集合默认选 ArrayList / HashMap，多线程用 ConcurrentHashMap；
  • checked 必须处理，unchecked 是代码 bug；
  • 泛型是编译期特性，运行时会被擦除。

Java 的知识面很宽，但基础部分其实就这么些。把这篇的内容吃透，再去看 Spring、MyBatis 这些框架，会顺畅很多——因为它们解决的问题，都是建立在这些基础之上的。
