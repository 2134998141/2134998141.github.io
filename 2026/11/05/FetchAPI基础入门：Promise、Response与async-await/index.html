fetch 看起来只有一行，但新手最容易在三个地方翻车：await 少写一次、404 没报错、以及想中止请求时不知道从哪下手。

这三个问题分别对应 Promise、HTTP 语义和浏览器 API 设计。按这条线走一遍，Fetch 就没有悬念了。

二、Promise 三种状态与两种写法

fetch 返回的 Promise 只有三种结局：

状态 触发条件 走哪个分支
pending 请求进行中 —
fulfilled 收到了任意 HTTP 响应 .then() / await
rejected 网络故障、CORS 拦截、请求被中止 .catch() / catch

四、Response 对象怎么读

方法 返回 典型用途
res.json() 对象 / 数组 JSON 接口
res.text() 字符串 HTML 片段、纯文本、排错时看原始响应
res.blob() Blob 图片、文件下载
res.formData() FormData multipart 响应
res.arrayBuffer() ArrayBuffer 二进制、流式处理
res.body ReadableStream 大文件、进度条

两个必须记住的限制：

  1. 响应体只能读一次。res.json() 之后再 res.text() 会抛 TypeError: body used already。想读两遍，先 const copy = res.clone()。
  2. 解析方法都是异步的，都要 await。

八、并发与竞态

多个互不依赖的请求别一个个 await，那样是串行的：

方法 行为 适用场景
Promise.all 全部成功才 resolve，任一失败立即 reject 页面初始化，缺一不可
Promise.allSettled 等全部结束，返回每个的结果与状态 允许部分失败
Promise.race 取最先落定的那个 超时控制、镜像源竞速
Promise.any 取最先成功的那个 多线路容灾

注意：并发不等于没有竞态。两个请求同时返回时，后发的可能先到，把旧数据覆盖到新页面上。搜索框那种场景要在响应回来后校验「这次请求是否还是最新的」，或者直接 abort 掉旧请求（上一节的做法）。

九、Fetch 与 XHR 对照

能力 XMLHttpRequest fetch
返回值 无，靠事件回调 Promise\
404 / 500 靠 status 判断 靠 res.ok 判断，不自动 reject
超时 xhr.timeout + ontimeout AbortController + 定时器
取消 xhr.abort() ctrl.abort()
上传进度 xhr.upload.onprogress 需借助流，较麻烦
响应体 一次性 responseText 流，可 clone()
代码组织 易回调嵌套 天然适配 async/await

Fetch 不是「XHR 的完全替代」：需要精细上传进度时，XHR 反而更直接。但日常接口请求，Fetch 的可读性和组合性明显更好。

小结

  • fetch() 给 Response，res.json() 给数据，两次都要 await；
  • 404 / 500 仍会 fulfilled，必须手动检查 res.ok；
  • 响应体只能读一次，复用要先 res.clone()；
  • 传 FormData 不要手写 Content-Type；
  • 超时用 AbortController，记得在 finally 清定时器；
  • 无依赖请求用 Promise.all 并发，同时处理好竞态。
