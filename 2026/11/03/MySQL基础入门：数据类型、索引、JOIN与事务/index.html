MySQL 基础入门：数据类型、索引、JOIN 与事务

YuAn2026-11-032026-11-04

写业务代码的人早晚都要碰数据库。而绝大多数线上事故里，性能问题的源头都在 SQL 上：慢查询、索引失效、错误的 JOIN、事务没提交。

这篇不追求覆盖全部语法，只把「表怎么建、数据怎么查、索引怎么用、事务怎么保证不出错」这四件事讲透。

一、先连上

字符集一定要用 utf8mb4。MySQL 里那个叫 utf8 的字符集其实是残缺的，只支持 3 字节，存 emoji 会直接报错。

二、数据类型怎么选

建表时最纠结的就是类型选择，记住几条原则：

类型 场景 注意
INT 主键、数量 4 字节，够用到 21 亿
BIGINT 用户 ID、订单号 8 字节，大表主键优先
DECIMAL(10,2) 金额 不要用 FLOAT/DOUBLE 存钱
VARCHAR(64) 昵称、标题 变长，但别乱开 255
TEXT 长内容 不走内存临时表，尽量少用
DATETIME 创建时间 8 字节，和时区无关
TIMESTAMP 更新时间 4 字节，受时区影响，2038 年溢出
TINYINT(1) 布尔值 MySQL 没有真正的 boolean

三条实用建议：

  1. 金额用 DECIMAL，浮点数会有精度误差（0.1 + 0.2 != 0.3 在数据库里同样成立）；
  2. 时间用 DATETIME，TIMESTAMP 的 2038 年问题早晚会来；
  3. 字符串长度按实际需求给，VARCHAR(255) 当万能类型用会拖慢排序和临时表。

四、索引：为什么查询慢

索引是 MySQL 里投入产出比最高的知识。

InnoDB 的索引是一棵 B+ 树，三个特点决定了它的性能：

  1. 非叶子节点只存索引值，不存数据 → 一个节点能放更多键 → 树更矮。三层 B+ 树就能存两千万行左右的数据，查一次最多读三次磁盘；
  2. 所有数据都在叶子节点，且按索引顺序排列 → 范围查询只需顺着叶子链表走；
  3. 叶子节点用双向链表相连 → BETWEEN、ORDER BY 这类操作非常高效。

什么时候该建索引

  • 经常出现在 WHERE 里的列
  • 用于 JOIN 的关联列
  • 用于 ORDER BY / GROUP BY 的列
  • 唯一性约束的列

什么时候索引会失效

这是最容易被忽略的部分：

联合索引的最左前缀

这个索引能支持：

  • WHERE a = ?
  • WHERE a = ? AND b = ?
  • WHERE a = ? AND b = ? AND c = ?

不能支持：

  • WHERE b = ?（跳过了 a）
  • WHERE a = ? AND c = ?（c 只能用上 a 的部分）

所以联合索引的字段顺序很重要：区分度高的放前面，等值查询的放前面，范围查询的放最后。

用 EXPLAIN 看执行计划，重点看三列：

列 看什么
type const / ref / range 好，ALL 是全表扫描
key 实际用了哪个索引，NULL 表示没走索引
rows 预估扫描行数，越小越好

三个实战要点：

1. LEFT JOIN 的过滤条件放哪很重要

因为 WHERE 是在 JOIN 之后执行的，右表为 NULL 的行会被 o.status = 1 直接过滤掉。

2. 一对多 JOIN 会产生重复行

一个用户有多笔订单，JOIN 后用户信息会重复出现。统计时要加 DISTINCT 或用子查询。

3. 别 JOIN 太多表

超过 3 张表的 JOIN，执行计划容易走偏。宁可拆成两次查询在应用层拼装。

六、事务：保证数据不出错

事务解决的是「一组操作要么全成功，要么全失败」的问题。最典型的例子是转账：

ACID 四个特性

特性 含义
A 原子性 要么全做，要么全不做
C 一致性 事务前后数据满足约束
I 隔离性 并发事务互不干扰
D 持久性 提交后即使断电也不丢

四种隔离级别

级别 脏读 不可重复读 幻读
READ UNCOMMITTED 可能 可能 可能
READ COMMITTED 不可能 可能 可能
REPEATABLE READ（默认） 不可能 不可能 InnoDB 用间隙锁基本解决
SERIALIZABLE 不可能 不可能 不可能

MySQL 的 InnoDB 默认是 REPEATABLE READ，大多数场景够用。只有明确需要时才调高，因为隔离级别越高并发越差。

三个注意事项

  1. 事务要短。事务里不要做网络请求、不要等用户输入，否则锁会一直持有；
  2. UPDATE 要命中索引。没走索引的行锁会升级成表锁，直接把并发打没；
  3. 注意隐式提交。DDL 语句（CREATE、ALTER、DROP）会隐式提交当前事务。

七、十条实用建议

  1. 字符集统一 utf8mb4；
  2. 金额用 DECIMAL，不用浮点；
  3. 主键用自增 BIGINT，别用 UUID（随机写入会撕裂 B+ 树）；
  4. 每张表都要有主键；
  5. 建表时先想好索引，别等慢了再补；
  6. 索引列上不要用函数、不要左模糊、不要隐式转换；
  7. SELECT 只取需要的列，别写 SELECT *；
  8. 分页深翻页用「游标」而不是大 OFFSET；
  9. 批量插入用一条 INSERT 带多组 VALUES；
  10. 上线前用 EXPLAIN 过一遍新增的慢 SQL。

小结

  • 类型选对，后面少一半麻烦；
  • 索引是 B+ 树，非叶子只存索引、数据全在叶子、叶子之间有链表；
  • 索引失效的三大元凶：函数、左模糊、隐式转换；
  • LEFT JOIN 的过滤条件写 ON 里，写 WHERE 里会变成内连接；
  • 事务要短，UPDATE 要命中索引。

数据库这块，语法只是门槛，真正拉开差距的是对索引和执行计划的理解。
